Què és Git i per a què serveix?
control de versions distribuït
  • Git és un sistema de control de versions: guarda un historial complet de tots els canvis fets en un projecte.
  • Permet tornar a qualsevol versió anterior del codi en qualsevol moment.
  • Facilita la col·laboració: diverses persones poden treballar al mateix projecte sense trepitjar-se els canvis.
  • Funciona localment (al teu ordinador) i pot sincronitzar-se amb serveis remots com GitHub.
  • GitHub és una plataforma web que allotja repositoris Git al núvol i afegeix eines de col·laboració.
📸
Historial de canvis
Cada commit és una "foto" del projecte. Pots veure qui va canviar cada línia i quan.
🌿
Branques (branches)
Treballes en una còpia paral·lela del codi sense afectar la versió principal fins que estàs llest.
👥
Col·laboració
Diversos desenvolupadors treballen en el mateix projecte i fusionen els seus canvis de forma controlada.
⏪
Revertir canvis
Si alguna cosa falla, pots tornar a qualsevol versió anterior del projecte amb una sola comanda.

Instal·lació i Configuració inicial
primer cop que uses git
  • Descarrega Git des de git-scm.com. En Linux, usa el gestor de paquets.
  • Comprova que s'ha instal·lat correctament amb git --version.
  • Abans de res, configura el teu nom i correu: Git els associa a cada commit que fas.
  • Aquesta configuració es desa globalment i no cal repetir-la per a cada projecte.

Verificar la instal·lació

git --version # Hauria de mostrar quelcom com: git version 2.43.0

Configuració inicial (fer-ho una sola vegada)

# El teu nom (apareixerà als commits) git config --global user.name "El teu Nom" # El teu correu (ha de coincidir amb el de GitHub) git config --global user.email "correu@exemple.com" # Editor per defecte (VS Code) git config --global core.editor "code --wait" # Nom de la branca principal (estàndard actual) git config --global init.defaultBranch main # Comprovar tota la configuració git config --list
💡 El correu que poses a user.email ha de ser el mateix que tens a GitHub, perquè els commits quedin associats al teu perfil correctament.
💡 Clau → Configura nom i correu una sola vegada amb --global. Afecta tots els repositoris del teu ordinador.

Comandes Bàsiques
el cicle de vida d'un canvi
  • El flux bàsic de Git és: modificar arxius → afegir a l'stage → fer commit.
  • L'stage (àrea de preparació) és un espai intermedi on tries quins canvis vols incloure al pròxim commit.
  • Un commit és una instantània permanent dels arxius afegits a l'stage, amb un missatge descriptiu.

repositori remot

Iniciar i clonar repositoris

git init
Inicialitza un nou repositori Git a la carpeta actualCrea la carpeta oculta .git
git clone <url>
Copia un repositori remot al teu ordinadorEx: git clone https://github.com/usuari/repo.git
git clone <url> <nom>
Clona el repositori amb un nom de carpeta personalitzat

Veure l'estat i l'historial

git status
Mostra quins arxius han canviat, quins estan a l'stage i quins no s'han afegitLa comanda que més usaràs
git log
Mostra l'historial de commits amb hash, autor, data i missatge
git log --oneline
Historial compacte: un commit per líniaMolt més llegible per veure l'evolució del projecte
git diff
Mostra les línies exactes que han canviat des de l'últim commit

Afegir canvis i fer commits

git add <arxiu>
Afegeix un arxiu concret a l'stageEx: git add index.html
git add .
Afegeix tots els arxius modificats a l'stageEl punt significa "tot el directori actual"
git commit -m "missatge"
Fa un commit amb els canvis de l'stage i un missatge descriptiuEx: git commit -m "Afegeix formulari de contacte"
git commit -am "missatge"
Afegeix tots els arxius modificats i fa el commit en una sola comandaNo inclou arxius nous (untracked)

Desfer canvis

git restore <arxiu>
Descarta els canvis d'un arxiu i el torna a l'últim commit⚠️ Els canvis es perden definitivament
git restore --staged <arxiu>
Treu un arxiu de l'stage (però manté els canvis al fitxer)
git revert <hash>
Crea un commit nou que desfà els canvis d'un commit anteriorManera segura de desfer sense reescriure l'historial

Exemple de sessió típica

# Veiem quins arxius han canviat git status On branch main Changes not staged for commit: modified: index.html Untracked files: styles.css # Afegim tots els canvis a l'stage git add . # Fem el commit amb un missatge clar git commit -m "Millora el disseny de la pàgina principal" # Veiem l'historial compacte git log --oneline a1b2c3d Millora el disseny de la pàgina principal 9f8e7d6 Afegeix secció de contacte 3c4d5e6 Commit inicial
⚠️ Bons missatges de commit: escriu missatges en imperatiu i descriptius. ✅ "Afegeix validació del formulari" vs ❌ "canvis" o "arreglo coses".
💡 Clau → El cicle és sempre: git status → git add . → git commit -m "missatge". Fes commits petits i freqüents amb missatges clars.
🌿
Branques (Branches)
línies de desenvolupament paral·leles
  • Una branca és una línia de desenvolupament independent: els canvis que fas no afecten les altres branques.
  • La branca principal s'anomena main (o master en projectes antics): conté el codi estable.
  • Es creen branques per a noves funcionalitats, correccions d'errors o experiments.
  • Un cop llest, la branca es fusiona (merge) a main i es pot eliminar.

Diagrama de branques

main ●───────────────────────────────●──● v1.0 \ / feature/login ●───●───●──────/ \ / feature/navbar ●───●──/

Gestió de branques

git branch
Llista totes les branques localsLa branca activa es marca amb *
git branch <nom>
Crea una nova brancaEx: git branch feature/login
git switch <nom>
Canvia a una branca existentEquivalent modern de git checkout
git switch -c <nom>
Crea una branca nova i canvia a ella directamentLa comanda més habitual per iniciar una funcionalitat
git merge <nom>
Fusiona la branca indicada a la branca actualPrimer fes switch a main, després git merge feature/login
git branch -d <nom>
Elimina una branca ja fusionadaUsa -D per forçar si no s'ha fusionat

Exemple: crear i fusionar una branca

# Creem i canviem a la nova branca git switch -c feature/pagina-contacte # Treballem i fem commits a la nova branca git add . git commit -m "Afegeix pàgina de contacte" # Tornem a main i fusionem git switch main git merge feature/pagina-contacte # Eliminem la branca ja fusionada git branch -d feature/pagina-contacte
⚠️ Conflictes de merge: si dos desenvolupadors modifiquen les mateixes línies d'un arxiu, Git no sap quin canvi escollir i genera un conflicte. Cal resoldre'l manualment editant l'arxiu i fent un commit nou.
💡 Clau → Norma d'or: mai treballis directament a main. Sempre crea una branca nova per a cada funcionalitat o correcció.
🐙
GitHub
repositoris al núvol i col·laboració
  • GitHub és la plataforma de referència per allotjar repositoris Git i col·laborar en projectes.
  • Un repositori (repo) a GitHub conté tot el codi, l'historial de commits i les branques del projecte.
  • Permet treballar en equip amb eines com Pull Requests, Issues i Actions.
  • Els repositoris poden ser públics (accessibles a tothom) o privats (només per a convidats).
🔀
Pull Request (PR)
Sol·licitud per fusionar una branca a main. Permet revisió del codi per part de l'equip abans de fusionar.
🐛
Issues
Sistema de tasques i informes d'errors. Permet organitzar i assignar feina a l'equip.
⚡
GitHub Actions
Automatització de tasques: tests automàtics, desplegament, validacions en cada push.
🍴
Fork
Copia un repositori aliè al teu compte per modificar-lo sense afectar l'original.

Crear un repositori a GitHub

# Opció A: Crear repositori nou des de zero (a GitHub.com primer) # Després, connectar-lo al teu projecte local: git remote add origin https://github.com/usuari/nom-repo.git git push -u origin main # Opció B: Clonar un repositori existent de GitHub git clone https://github.com/usuari/nom-repo.git
💡 Clau → Crea el repositori a GitHub.com, copia la URL i usa git remote add origin + git push. A partir d'aquí, tot el teu codi quedarà guardat al núvol.
☁️
Treballar amb el Repositori Remot
sincronitzar local i GitHub
  • El repositori remot (origin) és la còpia del projecte allotjada a GitHub.
  • git push puja els teus commits locals al remot. git pull baixa els canvis del remot al local.
  • Sempre fes git pull abans de començar a treballar per tenir el codi actualitzat.

Comandes de sincronització

git remote -v
Mostra els repositoris remots connectats i les seves URLs
git push
Puja els commits de la branca actual al remotLa primera vegada: git push -u origin main
git push origin <branca>
Puja una branca concreta al remotEx: git push origin feature/login
git pull
Baixa i fusiona els canvis del remot a la branca actualEquivalent a git fetch + git merge
git fetch
Baixa els canvis del remot però NO els fusionaPermet revisar-los abans de fusionar
git push --delete origin <branca>
Elimina una branca del repositori remot

Git amb Visual Studio Code
integració visual i terminal integrada
  • VS Code té integració nativa amb Git: no cal instal·lar cap extensió extra.
  • La barra lateral d'Source Control (icona de branques) mostra els arxius modificats i permet fer commits.
  • El terminal integrat de VS Code és el lloc ideal per executar comandes Git.
  • Extensions com GitLens afegeixen funcionalitats avançades com veure qui va escriure cada línia.

Obrir el terminal integrat de VS Code

Ctrl + `
Obre/tanca el terminal integrat de VS CodeEl backtick és la tecla a l'esquerra del 1
Ctrl + Shift + `
Obre un terminal nou (si ja n'hi ha un d'obert)
Ctrl + Shift + G
Obre el panell de Source Control (control de versions visual)

Flux complet i .gitignore
bones pràctiques i referència ràpida

El fitxer .gitignore

  • El fitxer .gitignore indica a Git quins arxius o carpetes mai ha de controlar.
  • S'usa per excloure: dependències (node_modules/), arxius de configuració local, claus secretes, arxius temporals…
  • Ha d'estar a l'arrel del projecte i es commiteja com qualsevol altre arxiu.
# Exemple de .gitignore per a un projecte web # Dependències node_modules/ # Variables d'entorn (claus secretes, credencials) .env .env.local # Arxius de configuració dels editors .vscode/settings.json .idea/ # Arxius del sistema operatiu .DS_Store # macOS Thumbs.db # Windows # Carpetes de build dist/ build/

Flux complet: primer projecte a GitHub

### PAS 1: Crear la carpeta i inicialitzar Git ### mkdir el-meu-projecte cd el-meu-projecte git init code . # Obre VS Code a la carpeta ### PAS 2: Crear arxius i fer el primer commit ### # Crea index.html, styles.css... des de VS Code git add . git commit -m "Commit inicial" ### PAS 3: Connectar amb GitHub ### # (Primer crea el repositori buit a github.com) git remote add origin https://github.com/usuari/el-meu-projecte.git git push -u origin main ### PAS 4: Flux diari de treball ### git pull # Actualitzar git switch -c feature/nova-funcio # Nova branca # ... treballes als arxius ... git add . git commit -m "Afegeix nova funcionalitat" git push origin feature/nova-funcio # Puja la branca # ... crea un Pull Request a GitHub ...
✅ Bones pràctiques resumides: commits petits i freqüents · missatges descriptius · sempre treballar en branques · fer pull abans de push · mai pujar credencials ni node_modules.
💡 Clau → Git és una habilitat fonamental per a qualsevol desenvolupador. Dominar el cicle add → commit → push i treballar amb branques és suficient per al 90% dels casos del dia a dia.

Pràctica: Treball en equip amb branques
activitat per a 2 persones · durada ~20 min
  • Practicareu el flux real de treball: un crea el repositori, l'altre col·labora des de la seva màquina.
  • Cadascú treballarà en una branca pròpia i veureu com els canvis es fusionen a main.
  • Necessiteu: 2 ordinadors, 2 comptes de GitHub i VS Code instal·lat.
👥 Al llarg de la pràctica, Persona A és qui crea el repositori i Persona B és el col·laborador convidat. Els passos indiquen clarament qui fa cada cosa.

PAS 1 — Persona A: Crea el repositori i l'arxiu inicial

# Crea una carpeta i inicialitza Git mkdir practica-equip cd practica-equip git init code . # Crea un arxiu index.html amb contingut mínim i guarda'l # (des de VS Code, crea l'arxiu manualment) git add . git commit -m "Commit inicial: index.html"
📋 Contingut mínim per a l'index.html inicial:

<!DOCTYPE html>
<html lang="ca">
<head><meta charset="UTF-8"><title>Pràctica Git</title></head>
<body>
<h1>Pràctica de treball en equip amb Git</h1>
</body>
</html>

PAS 2 — Persona A: Puja el repositori a GitHub i convida la Persona B

1. Crea un repo a GitHub
Ves a github.com → New repository → nom: practica-equip → CreateDeixa-ho públic i sense README
2. Connecta i puja
Copia la URL del repo i executa les comandes del costat →
git remote add origin https://github.com/personaA/practica-equip.git git push -u origin main Branch 'main' set up to track remote branch 'main' from 'origin'.
3. Convida la Persona B
GitHub → Settings del repo → Collaborators → Add people → escriu el nom d'usuari de la Persona BLa Persona B rebrà un correu per acceptar la invitació

PAS 3 — Persona B: Clona el repositori

# Accepta la invitació de GitHub primer (comprova el correu) # Clona el repositori de la Persona A git clone https://github.com/personaA/practica-equip.git cd practica-equip code . # Comprova que veus l'index.html de la Persona A git log --oneline a1b2c3d Commit inicial: index.html

PAS 4 — Cadascú treballa a la seva pròpia branca

👤
Persona A
Afegeix un paràgraf de benvinguda a l'index.html
👤
Persona B
Afegeix un peu de pàgina (<footer>) a l'index.html
### PERSONA A (al seu ordinador) ### git switch -c feature/benvinguda # Edita index.html: afegeix dins <body>: # <p>Benvinguts a la nostra web de pràctiques!</p> git add . git commit -m "Afegeix paràgraf de benvinguda" git push origin feature/benvinguda ### PERSONA B (al seu ordinador) ### git switch -c feature/footer # Edita index.html: afegeix abans de </body>: # <footer><p>Pràctica Git — 2025</p></footer> git add . git commit -m "Afegeix footer a la pàgina" git push origin feature/footer

PAS 5 — Persona A: Fusiona les dues branques a main

# Tornem a main i baixem els canvis remots git switch main git pull # Fusionem la branca de la Persona A git merge feature/benvinguda Updating a1b2c3d..b2c3d4e Fast-forward index.html | 1 + # Baixem la branca de la Persona B del remot i la fusionem git fetch origin git merge origin/feature/footer Merge made by the 'ort' strategy. index.html | 1 + # Pugem el resultat fusionat a main git push # Eliminem les branques ja fusionades git branch -d feature/benvinguda git push --delete origin feature/footer

PAS 6 — Persona B: Actualitza el seu local

# Torna a main i baixa el resultat final git switch main git pull # Comprova que veu els canvis dels dos al index.html git log --oneline d4e5f6g Merge branch 'feature/footer' c3d4e5f Afegeix footer a la pàgina b2c3d4e Afegeix paràgraf de benvinguda a1b2c3d Commit inicial: index.html

Resum de la pràctica

PasQuiAcció
1Persona ACrea el repo, fa el commit inicial i el puja a GitHub
2Persona AConvida la Persona B com a col·laboradora
3Persona BAcepta la invitació i clona el repositori
4Persona A + Persona BCadascú crea la seva branca, fa el seu canvi i el puja
5Persona AFusiona les dues branques a main i puja el resultat
6Persona BFa pull i comprova que veu els canvis dels dos
🎯 Heu acabat! Heu practicat: crear un repositori compartit, treballar en branques separades, pujar canvis a GitHub i fusionar-los a main. Aquest és el flux real que s'usa en empreses de desenvolupament.
💡 Clau → En equip, cada persona treballa a la seva branca i mai directament a main. La fusió la gestiona una sola persona per evitar conflictes. En projectes reals s'usarien Pull Requests a GitHub per fer la revisió.
